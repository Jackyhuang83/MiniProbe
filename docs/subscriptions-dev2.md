# MiniProbe 订阅管理中心 DEV2：续费历史与提醒

本阶段基于 DEV1 私有账本，新增只允许 Server 本机 root SSH 写入的续费历史与到期提醒；不修改 Agent、监控 API 和原有 VPS 月租/到期字段，不增加新端口。

## 验证路径

1. 使用开发 PR 构建的 Server 做隔离测试，或 PR 经审核合并并发布下一个 Server 版本后，在 VPS SSH 执行 `miniprobe` → `15. 订阅管理中心`。
2. 选择 `7. 查看 / 记录续费`：可追加不可修改的实际续费事件，记录日期、实际币种/金额、备注；手动订阅可选输入新的到期日，两者原子保存；VPS 续费历史只记录，不修改节点配置。
3. 选择 `8. Telegram 到期提醒`：**默认关闭**，需要已有 Telegram Bot/Chat ID 且 Telegram 总开关开启，主动选择启用后才可能发送订阅提醒。提醒阶段支持 0–90 天及 -1（逾期一次），默认 30/7/3/1/0/-1。
4. 选择 `9. 单条订阅提醒设置`：可继承全局、关闭本条、指定单独的提醒阶段，包括自动关联的 VPS。
5. 进入 HTTPS 私有订阅中心，在独立密码验证后可查看最近 12 条续费事件和提醒开启情况；公网订阅 API 仍为只读，匿名请求 401，Public Dashboard 的 Cookie 不能替代订阅密码。
6. 另行测试 Telegram 到期提醒时，只对可接受真实提醒的测试订阅启用；切勿将 Bot Token、Chat ID 或私密费用发到 Issue/PR 日志。

## 规则与安全边界

- 所有事件追加到独立 `subscriptions.json`；事件单次写入同时更新手动订阅的新到期日，失败不得只写入其中一部分。历史不可通过管理 API 修改或删除。上限 512 条事件。
- 整个账本保持 0600、1 MiB 大小限制，提醒回执最多 1536 条、按 180 天淘汰旧回执；单项覆盖最多 128 条。超过上限明确失败，不无限增长。
- 时区使用每条记录的 IANA `time_zone`；按当地日历日期计算天数，避免夏令时产生 23/25 小时的误差；VPS 默认使用 Asia/Tokyo。
- 提醒每小时检查一次，并在 Server 启动时检查。每条仅针对当前 `subscription_id + 到期日期 + 提醒阶段` 提醒，回执先持久化；发送成功再记为 delivered，防止每次检查重复发送。失败后最多 5 次指数间隔重试（1/2/4/8 小时），超过次数不重复发送。
- 启用时错过提前提醒窗口会进入当前应适用的阶段；逾期阶段在到期后 30 天内补发一次。只有状态为 active 且有有效到期日期的条目提醒；暂停、取消、长期或无日期不提醒。
- Telegram 文本仅包含订阅服务名、到期日期及倒计时；不包含费用、密码、令牌、支付详情。Telegram 通知非自动付款。
- 已发送但尚未落盘时宕机可能引发一次重复通知，跨外部服务无法保证严格 exactly-once；其余重启后会使用落盘回执防重。
- 旧版 DEV1 `subscriptions.json` 无新增字段时仍可加载；新版本保留原所有字段；不会写入旧版 `miniprobe.json`。
- 不开放网页增删改、不实现订阅日历/备份/月年度总价，这些属于 DEV3 或独立安全审核。

## CI

`go test ./...`、`go vet ./...`、`node --check cmd/miniprobe-server/web/subscriptions.js` 与 `make release`。新增测试覆盖金额及日期校验、闰年/夏令时/JST 时区边界、历史重启持久性、VPS 不写回、阶段去重、失败重试、单项关闭、默认关闭及 HTTPS 独立 owner 授权。
