# MiniProbe 订阅中心 — 邮箱一次性验证码

## 第一次启用
1. 在 MiniProbe Server VPS SSH 执行 `miniprobe`，进入 `15 → 11 → 1`。
2. 填入 SMTP 主机、端口（465 TLS 或 587 STARTTLS）、SMTP 用户名、发件邮箱、固定接收邮箱，并输入服务商提供的**专用 SMTP App Password/授权码**，不要粘贴普通邮箱登录密码、115 Cookie 或其它敏感 Token。
3. 确认发送测试邮件；测试成功且配置写入后才开启邮箱验证登录。请检查收件箱/垃圾邮件。
4. 经现有 Cloudflare Tunnel HTTPS 进入 MiniProbe 订阅中心，点击「忘记密码？使用邮箱一次性验证码」，获取 8 位验证码并输入。验证码 10 分钟失效，最多尝试 5 次，仅限发起请求的浏览器使用，且只能成功使用一次。
5. 如需变更独立密码，邮箱登录后在顶部「通过邮箱验证重设密码」表单内完成。邮箱重设权限仅持续 10 分钟；如果过期，可重新获取验证码。
6. 解绑：`miniprobe → 15 → 11 → 2`，输入 `DISABLE`，从本地配置文件删除 SMTP 授权码并立即禁用邮箱登录。原密码登录继续有效。

## 服务器、网络与安全
- 不需要进入 Docker 容器。SSH 的 `miniprobe` 自动进入 Docker 管理菜单；SMTP 配置通过已有本地 Unix Socket 生效。
- 只能填写**固定收件邮箱**，网页不能填目标邮箱、更换邮箱或读取当前完整邮箱地址。
- SMTP 配置位于 Docker 数据卷的 `subscriptions-email.json`，持有 SMTP 授权码的文件权限为 `0600`（运行 UID 10001）。SMTP 授权码**在本机以可恢复使用的形式保存**，因此磁盘被取得或全量备份被泄露时可能泄露邮件授权；务必使用权限最小的专用 SMTP 授权码，并保护本地备份。
- 所有 SMTP 连接验证 TLS 服务器证书；不降级为未加密 SMTP。若 VPS 无法访问 465/587 端口或服务商禁用 SMTP，测试会失败，系统不会启用新的恢复配置。
- 发送限制至少 60 秒一次、服务全局每小时最多 6 次；收件固定，防止短信/邮件轰炸与开放邮件中继。挑战标识保存在严格同站 HttpOnly Cookie，服务端只在内存中保存代码的 HMAC 摘要。
- 只有邮箱 OTP 登录后才发放 10 分钟密码重设权限；一般 Dashboard 登录和普通订阅密码登录不能单独获取此权限。
- SMTP 不依赖 PHP/Node.js，无第三方服务端邮件转发 API。邮件投递速度及可用性仍取决于所选邮箱服务商。

## 万一忘记密码或邮箱失效
- 即使邮箱服务不可用，也可以直接 VPS SSH `miniprobe → 15 → 6` 设置新订阅密码；恢复不依赖外部邮件平台。
- 如果收不到邮件，请先检查垃圾邮件和 SMTP 授权码是否有效，再在本地菜单 `15 → 11` 重新发送测试邮件。
